# 公众号图文设计

把文案、照片或插画、品牌素材与导出视为同一个设计任务。根据内容目的选择叙事结构、画风与交付形式，制作能使用的公众号文章或长图，并检查真实手机阅读效果。

## 先建立素材与交付清单

- 阅读现有成品与项目约定，再改进；保留用户已认可的内容与设计方向。
- 从请求确定读者、目的、内容类型、语言、品牌原件与交付形式。区分活动前预告、活动后回顾、人物参会或发言、公司进展与祝福寄语；仅追问影响结果且无法推断的信息，其余做合理判断并继续。
- 活动报道、公司动态或需要选择文章结构时，读 [内容类型与叙事](references/content-types.md)。先核对时间状态、人物身份和资料来源，再写标题与正文；议程中的计划不等于已经发生，观点不等于业务成果。
- 确认品牌称呼与事实，不补造人物引语、职务、合作成果或业务数据。祝福类文案真诚克制；活动与公司动态围绕已确认的信息和读者价值展开。
- 按需要选择标题、摘要、正文、横版/方版封面、长图、切片、编辑页，不强制每次输出整套。示例尺寸是起点，不等于平台最新硬性规定；若用户要求按当前平台规范，查阅官方文档或已授权后台。
- 真实活动优先使用用户提供或授权的现场照片、议程、演讲资料及主办方视觉；缺少现场图时可用已确认资料构图或明确为示意的视觉，不生成冒充现场记录的照片。
- 对品牌和现有图片先做视觉检查。需要新插画或图片编辑时使用当前可用的图像生成/编辑工具并遵循其规则；没有工具时用已有授权素材，不伪称已经生成图片。

## 建立可读、统一的构图

详细判断见 [设计与品牌](references/design-and-brand.md)。

1. 按目的选择信息层级：预告强调时间地点与看点，回顾强调已发生的内容与现场，公司动态强调变化与影响，祝福强调情感。段数、字体与装饰随主题调整；不默认套用节日文案、书法标题、月色或花枝。再定义标题、正文、注释层级及颜色。
2. 按章节安排配图的叙事作用、主体与构图，先看全篇是否重复使用同一场景；不需要每章都配图。多配图长文或重复、接缝问题见 [配图连续性](references/artwork-continuity.md)。
3. 根据素材选择融合方式：真实照片可完整保留矩形画幅，用取景、图注、边距和底色连接正文；透明插画只是辅助素材的一种选择。生成插画时明确“无文字、无 Logo、指定区域低细节留白”，精确文字和原始 Logo 在可控排版工具中叠放。检查最终可见边缘，不以接近的色值或文字对比度通过代替融合检查。
4. 先检查 Logo 的真实 alpha 与白色像素。默认直接使用原始透明文件，不重绘、不拉伸、不任意改色。只有取得几何完全对齐的可信透明轮廓，才考虑配对 alpha；检查方法与例外见参考文档。
5. 在最终背景和手机缩放下复核所有文字；提高文字与背景的反差，或移到安静区域。小字以至少 4.5:1 的对比作为检查基线；像素采样只是问题筛查，不能代替视觉检查或完整无障碍审核。

## 制作与交付

实现及边界见 [公众号交付](references/wechat-delivery.md)。

- 采用可重建的源稿。将可编辑文案、布局源文件、原始素材、生成图片记录和输出文件分开存放。
- 需要精确视觉版时：输出完整长图，按需提供自然切分的切片及单独构图的封面。避免仅把长图机械缩小当封面。
- 需要可编辑版时：正文使用原生文字与必要配图，尽量使用内联样式；复制范围只含正文。附标题、摘要、独立配图和顺序说明。
- 本技能提供 Node.js 辅助脚本，安装和参数见 [脚本用法](references/scripts.md)。这些脚本服务于设计，不限制你使用更适合项目的工具。
- 草稿要按品牌和活动隔离。修改图片时用稳定素材 ID 迁移来源，保留用户编辑的文字。`file://` 下遮罩和剪贴板可能与 HTTP 不同，应测试用户实际打开方式。
- 不擅自加入署名、创作说明、营销尾注或新文案；遵循用户对可见内容的要求，且如实回答任何关于素材来源的直接提问。

## 完成前验证

- 对照资料复核活动状态、日期地点、人物与职务、引语、图注和公司动态中的数据；图文与时间线应一致，不能把往届照片当作本次现场。
- 查看本次交付的完整图文、章节交界、配图缩略图、封面和切片，再按手机宽度复核。发现非刻意的重复场景、透明插画的意外底片、被遮罩切断的主体或明显接缝时，先修改再交付；同时确认无断字、漏图、裁掉 Logo 或文字、字号过小等问题。真实照片的有意边框或完整画幅不算融合失败。
- 多配图正文运行 [配图检查](references/artwork-audit.md)（`node scripts/audit-artwork.cjs artwork.json`）或等效检查，核对重复来源，并按素材类型解读透明统计与边缘警告；含透明插画时复核底片与轮廓，真实照片重点检查取景及版面连接。合理重复记录具体理由；报告不替代成品视觉判断。
- 交付文章页时，至少检查一个窄手机宽度和桌面宽度；需要适配时扩展到常用手机尺寸。确保横向不溢出、图片加载、标题摘要一致。
- 提供编辑器时，实际点击复制、保存和下载，检查复制内容、富文本图片数量、编辑后重开及素材升级。不能仅以按钮提示“成功”认定平台粘贴兼容。
- 检查导出包与最新预览来自同一版源稿。交付清楚的入口与文件链接，说明可编辑文字和图片内文字的区别。
- 未实际验证微信后台的图片接受和排版时，明确仍需后台预览；不要宣称已经发布。仅在用户明确授权发布时继续账号操作。

## 可复用起点

`assets/starter/` 是无品牌的秋日来信技术示例，展示排版与导出配置。制作活动报道或公司动态时，重写内容结构并换入适合的真实资料和视觉；示例中的主题、配色、字体、段数与尺寸都不是默认要求。
