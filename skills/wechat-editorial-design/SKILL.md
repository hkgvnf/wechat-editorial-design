# 公众号图文设计

把文案、插画、品牌素材与导出视为同一个设计任务。优先交付能打开、能复制、能用于发布的文件，并检查真实手机阅读效果。

## 先建立素材与交付清单

- 阅读现有成品与项目约定，再改进；保留用户已认可的内容与设计方向。
- 从请求确定读者、目的、语言、品牌原件、主题、交付形式。仅追问影响结果且无法推断的信息；其余做合理判断并继续。
- 确认文案中的品牌称呼与事实。供应商、合作伙伴祝福应真诚、具体、克制，不补造业务成绩、承诺、促销或联系信息。
- 记录需要的标题、摘要、正文、横版/方版封面、长图、切片、编辑页。示例尺寸是起点，不等于平台最新硬性规定；若用户要求按当前平台规范，查阅官方文档或已授权后台。
- 对品牌和现有图片先做视觉检查。需要新插画或图片编辑时使用当前可用的图像生成/编辑工具并遵循其规则；没有工具时用已有授权素材，不伪称已经生成图片。

## 建立可读、统一的构图

详细判断见 [设计与品牌](references/design-and-brand.md)。

1. 先把文字定稿为结构清楚的短段落，再安排视觉停顿。定义一套有限的标题、正文、注释层级及颜色，不让每个段落成为独立卡片。
2. 按章节安排配图的叙事作用、主体与构图，先看全篇是否重复使用同一场景；不需要每章都配图。多配图长文或重复、接缝问题见 [配图连续性](references/artwork-continuity.md)。
3. 为画面确定留白方向、主体位置、光感和色调。生成插画时明确“无文字、无 Logo、指定区域低细节留白”，把精确文字和原始 Logo 留在 HTML/CSS 或其他可控排版工具中。图与文共同构图；检查图片在最终底色上的所有可见边缘，不能以接近的色值或文字对比度通过代替融合检查。
4. 先检查 Logo 的真实 alpha 与白色像素。默认直接使用原始透明文件，不重绘、不拉伸、不任意改色。只有取得几何完全对齐的可信透明轮廓，才考虑配对 alpha；检查方法与例外见参考文档。
5. 在最终背景和手机缩放下复核所有文字；将浅色文字加深或移到安静区域。小字以至少 4.5:1 的对比作为检查基线；像素采样只是问题筛查，不能代替视觉检查或完整无障碍审核。

## 制作与交付

实现及边界见 [公众号交付](references/wechat-delivery.md)。

- 采用可重建的源稿。将可编辑文案、布局源文件、原始素材、生成图片记录和输出文件分开存放。
- 精确视觉版：输出完整长图、按章节自然切分的切片，以及单独构图的横版/方版封面。避免仅把长图机械缩小当封面。
- 可编辑版：正文使用原生文字与必要配图，尽量使用内联样式；复制范围只含正文。附标题、摘要、独立配图和顺序说明。
- 本技能提供 Node.js 辅助脚本，安装和参数见 [脚本用法](references/scripts.md)。这些脚本服务于设计，不限制你使用更适合项目的工具。
- 草稿要按品牌和活动隔离。修改图片时用稳定素材 ID 迁移来源，保留用户编辑的文字。`file://` 下遮罩和剪贴板可能与 HTTP 不同，应测试用户实际打开方式。
- 不擅自加入署名、创作说明、营销尾注或新文案；遵循用户对可见内容的要求，且如实回答任何关于素材来源的直接提问。

## 完成前验证

- 看完整长图、章节交界、所有配图缩略图及每张封面和切片，再按手机宽度复核。发现非刻意的重复场景、矩形底片、被遮罩切断的主体或明显接缝时，先修改再交付；同时确认无断字、漏图、裁掉 Logo 或文字、字号过小等问题。
- 多配图正文运行 [配图检查](references/artwork-audit.md)（`node scripts/audit-artwork.cjs artwork.json`）或等效检查，核对重复来源、透明统计及边缘警告。合理重复记录具体理由；报告不替代成品视觉判断，也不自动证明图文融合合格。
- 对文章页至少检查一个窄手机宽度和桌面宽度；需要适配时扩展到常用手机尺寸。确保横向不溢出、图片加载、标题摘要一致。
- 实际点击复制、保存和下载，检查复制内容、富文本图片数量、编辑后重开及素材升级。不能仅以按钮提示“成功”认定平台粘贴兼容。
- 检查导出包与最新预览来自同一版源稿。交付清楚的入口与文件链接，说明可编辑文字和图片内文字的区别。
- 未实际验证微信后台的图片接受和排版时，明确仍需后台预览；不要宣称已经发布。仅在用户明确授权发布时继续账号操作。

## 可复用起点

`assets/starter/` 是无品牌的秋日来信示例，展示留白、统一排版及导出配置。示意图形仅用于演示流程，不是正式品牌画面。按当次主题替换，避免把固定节日、配色、段数或尺寸当作本技能的要求。
