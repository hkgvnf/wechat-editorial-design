# 公众号交付与本地预览

在需要交付可复制文章、完整长图、正文切片和封面时阅读。公众号后台能力、尺寸限制与压缩行为会变化；以下是交付方法，不是平台永久规格。

## 先区分交付形态

| 形态 | 用途 | 需要说明的限制 |
| --- | --- | --- |
| 可编辑图文 | 在公众号编辑器继续修改文字 | 粘贴可能改变样式或丢失图片，需要后台预览 |
| 完整长图 | 审阅整体节奏、单独分享或存档 | 图中文字不是公众号正文中的可编辑文字 |
| 连续切片 | 按顺序上传，尽量保留设计效果 | 仍是图片，不应称为可编辑正文 |
| 横版与方版封面 | 对应不同展示位置 | 应分别构图，并核实当前后台的裁剪要求 |

如果用户需要两种使用方式，使用同一份文案和素材清单生成，避免两套内容逐渐不同。封面常见的约 2.35:1 与 1:1 可以作为初稿比例；交付时区分“设计比例”和“已在后台确认的要求”。

## 可编辑排版与一键复制

- 为正文创建独立的导出区域，只复制文章，排除工具栏、编辑按钮、使用说明和状态提示。
- 面向公众号的导出 HTML 以简单的块结构、内联样式和明确图片尺寸为主。复杂的定位、交互、CSS 遮罩和网页字体不应假定会被保留。
- 使用 `ClipboardItem` 写入 `text/html` 和 `text/plain` 时，应由用户点击触发，并处理权限与浏览器兼容性失败。
- `document.execCommand('copy')` 可作为环境允许时的降级方法，不能把“API 调用成功”当成粘贴效果已经验证。
- 图片使用本地路径、data URI 或网页 URL，都不能保证被目标编辑器接收。保留独立配图，并给出按位置补传的文件清单。
- 如无法访问公众号后台，只报告本地复制与预览的结果，明确后台粘贴、上传和手机预览仍未验证。

不要向用户承诺“一次粘贴即可完整还原”，除非实际目标编辑器的结果已经检查。可以提供简短可操作的替代路径：先粘贴正文，再按清单补传图片。

## 编辑保存与素材更新

只有需要让用户在本地修改内容时才加入编辑器和 `localStorage`；静态素材包不必增加这些功能。

建议将保存范围与身份分开：

```text
article:<brand-id>:<campaign-id>:draft
```

- 品牌和活动使用稳定、明确的标识，不共用全站通用的 `draft` 键，避免打开另一篇文章时恢复旧内容。
- 同一活动换配图时，保留同一个草稿键；素材版本作为单独字段维护，避免通过变更键名悄悄丢弃用户的文本修改。
- 优先保存结构化文本、允许编辑的段落和少量格式，按当前模板重新构建文章。避免直接保存整个旧 HTML 后，连旧图片和旧样式一起恢复。
- 如必须恢复 HTML，只保留允许的标签、属性与格式；移除脚本、事件属性及不可控地址。素材应按稳定的图片标识重新映射到最新清单。
- 版本迁移只更新已知图片或样式字段，保留用户修改的正文；不要用一次全局字符串替换覆盖任意用户内容。
- “重置正文”会丢弃本地修改，应清楚说明并由用户主动触发。
- 明确 `localStorage` 是当前浏览器、当前来源下的本地草稿，并非云备份；换浏览器、端口或从 `file://` 切到 HTTP 后可能无法读取原草稿。

## 本地文件与 HTTP 预览

本地 HTML 页面在 `file://` 下可能因浏览器的来源与 CORS 规则无法加载外部 CSS 遮罩，即使同一个文件用普通 `<img>` 可以显示。

如果使用 Logo 或装饰图作为 `mask-image`：

1. 在实际交付的打开方式下查看效果，不只检查开发服务器。
2. 对必要且大小可控的遮罩，可以使用正确 MIME 类型的 data URI 消除本地外部遮罩依赖。
3. 同时可以通过本地 HTTP 服务预览，让相对路径以明确的同源方式加载。
4. 对独立图文交付，若遮罩只是为了成品图，可在导出时把它合成到最终图片，避免要求公众号保留 CSS 遮罩。

data URI 只解决特定资源加载问题，不意味着公众号编辑器支持这种图片；HTTP 预览也不等于已发布到公网。不要依赖用户机器上原先存在的开发服务才能使用素材包。

## 切片、封面与素材包

- 按内容与画面结构选择切点，避免切断文字行、Logo、人脸或主要器物。可采用不同高度，除非目标平台要求固定尺寸。
- 连续切片保持相同宽度和色彩设置，用 `01_...`、`02_...` 等前缀明确顺序；顺序列表与实际文件一致。
- 若切片声称能无缝还原完整长图，应验证重组后尺寸和内容一致。无损切片可逐像素比对，有损切片应允许编码误差并查看边界。
- 封面分别检查主题、Logo 和必要文字的安全区；不要把方版简单当作横版中心裁切。
- 使用易读的目录名称，将最终成品与制作源文件区分。使用说明应写清选哪种交付、复制步骤、配图补传位置与切片顺序。
- 打包前核实引用、文件名、图片格式与压缩包内容；公开分享的模板不应夹带品牌私有素材、授权不明字体、个人路径或浏览器数据。

## 功能与交付验收

选择与本次交付相关的检查，不必为了静态修改构建完整测试套件：

- 手机与桌面预览均无横向溢出，文字可读，Logo 和配图完整。
- 复制得到的 HTML 只含文章区域；剪贴板读取可用时检查内容，并在独立编辑区粘贴复核。
- 修改一段文字、保存、刷新后仍在；不同活动不会互相覆盖。
- 在同一活动换素材后，文本修改保留，图片更新；如存在旧缓存，应验证迁移路径。
- 图片和链接从素材包解压后的相对位置仍能加载，必要的 data URI 无截断。
- 所有声称已更新的长图、切片、封面、HTML 和压缩包都确实重新生成。

交付说明应明确已检查的环境与未验证的目标环节；公众号后台的最终显示，应以实际后台预览和手机阅读效果为准。
