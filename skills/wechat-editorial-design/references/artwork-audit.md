# 配图重复与边缘检查

`scripts/audit-artwork.cjs` 是交付前的源素材检查，不是审美评分器。它检查一个正文目标中的可见 `img`，用 SHA-256 对源文件字节去重；改文件名、CSS 裁切或缩放不会绕过检查。不同封面与正文分别检查，不能把跨交付物的合理复用误报成一篇正文中的重复。

```json
{
  "html": "design.html",
  "target": "#poster",
  "query": "?mode=poster",
  "artSelector": "img.art",
  "ignoreSelector": ".logo",
  "outputDir": "output",
  "viewportWidth": 1080,
  "background": "#143a3f",
  "borderChannelThreshold": 12
}
```

在有 `playwright`、Chromium 和 `sharp` 的环境运行：

```sh
node scripts/audit-artwork.cjs artwork.json
```

结果写入 `output/artwork-report.json`。相对文件路径按配置文件所在目录解析，输入限可信本地 HTML。远程请求被拦截，图片字节只从本地文件或 data URI 读取。检查器不生成、不改色、不抠图，也不改写源素材。

## 重复素材如何处理

- `unacknowledgedDuplicateGroupCount` 大于零时，CLI 返回退出码 1，要求先解决重复。
- Logo 由 `ignoreSelector` 排除。同篇正文里，原则上为每个主要篇章安排独立图像和不同构图；不能只改裁切、透明度或位置就当成新配图。
- 有明确编辑理由时，只在实际允许重复的图片上加 `data-allow-repeat="具体理由"`。同一组允许一处作为原始使用，其他重复处都需非空理由；理由被逐项记录。不可批量标注来掩盖重复。
- 相同文件重新编码、预先裁切、轻微修图后字节会变化，需要看联系表和完整长图识别近似重复。脚本不会声称已识别视觉上的全部重复。
- 仅标注了允许重复、但没有重复发生的素材仍保留其理由，便于复核。

## 边缘颜色如何解读

检查器统计原图的全透明、半透明和不透明像素，并在四边均匀采样 RGBA。当不透明边缘像素与配置背景的任一 RGB 通道差大于阈值（默认 12）时，仅报告警告。自然枝叶、月色、纹理延伸到边缘，也可能产生合理警告。

CSS mask、opacity、filter、mix-blend-mode 和 clip-path 会记录在 `cssEffects`，它们可能改变最终边界，不能根据原图像素直接判定成品是否融合。反过来，原图边缘接近背景也不能证明最终无色块：需查看背景纹理、光照、渐变衔接和整个图片区域。

透明统计属于素材本身；透明不等于融合良好。不得为通过检查而把图全部透明化、过度压暗或强行改成单色。

## 必须补充的人工检查

1. 输出单篇正文的配图联系表，比较主体、视角、大小、留白方向与叙事用途。
2. 查看完整长图与手机实际阅读宽度，逐段检查图片是否贴合文字含义。
3. 检查四边与四角，包括章节连接处；确认没有矩形底板、明显色带、灰边或局部拼贴感。
4. 对边缘警告逐项解释，不能把“脚本无重复”称为“视觉已通过”。CSS 背景图、SVG 元素、canvas、完全遮挡和复杂空 mask 都需人工检查。
5. 用其他文字对比度检查补充可读性；本脚本不检查字体、文字对比或公众号后台兼容性。
